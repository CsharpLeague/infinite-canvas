# 模型渠道配置指南

模型渠道用于让登录用户通过项目后端调用第三方 AI 服务。前端选择模型后，后端会按模型名从已启用渠道中选择上游服务，并使用渠道中保存的 API Key 发起请求。

本文说明管理后台中的渠道配置。用户自己在右上角“配置”弹窗填写的本地直连渠道不在本文范围内。

## 配置前准备

先从服务商处确认以下信息：

- API Base URL，例如 `https://api.example.com` 或 `https://api.example.com/v1`
- API Key
- 服务协议：OpenAI 兼容或 KIE
- 服务商实际开放的模型名
- 模型支持的能力：文本、生图、图生图、视频或音频
- 服务商支持的请求路径和参数

只有“有一个域名、一个 Key 和一个模型名”并不能证明接口兼容。协议和请求路径必须与服务商文档一致。

## 新增渠道

进入“管理后台 → 系统设置 → 模型渠道”，新增渠道并填写以下字段。

| 字段 | 说明 |
| --- | --- |
| 渠道名称 | 仅用于后台识别和日志展示，例如“OpenAI 官方”或“AIHub 生图” |
| 协议 | 决定后端如何转换请求和任务结果，必须与上游接口一致 |
| 权重 | 同一个模型配置在多个启用渠道时的相对命中概率 |
| 请求超时（秒） | 后端等待上游响应的最长时间；生成类接口可使用较长时间 |
| 启用 | 关闭后，该渠道不会参与后端选路 |
| 接口地址 | 上游 Base URL，不要填写某个具体的生成接口 |
| API Key | 上游密钥；编辑已有渠道时留空表示沿用已保存的 Key |
| 渠道可用模型 | 该渠道允许后端调用的模型名，必须与上游要求完全一致 |
| 备注 | 可记录服务商、套餐、用途或特殊限制 |

修改后先保存渠道，再保存系统设置。

### 接口地址填写规则

系统会根据协议和功能继续拼接接口路径。接口地址应填写服务根地址或 API 版本根地址：

```text
https://api.example.com
https://api.example.com/v1
https://api.kie.ai/api/v1
```

不要填写完整业务接口：

```text
https://api.example.com/v1/images/generations
https://api.example.com/v1/chat/completions
https://api.kie.ai/api/v1/jobs/createTask
```

普通地址如果不以 `/v1`、`/api/v3` 或 `/api/plan/v3` 结尾，系统会自动追加 `/v1`。填写前应以服务商文档为准。

## 渠道类型选择

管理后台提供以下渠道类型：

- `New API`：推荐用于文本模型和标准 OpenAI Images 图像模型。
- `Sub2API`：推荐用于 OpenAI Responses 文本模型；生图兼容取决于具体部署版本。
- `火山方舟`：用于 Seedance 官方内容生成任务接口。
- `通用 OpenAI`：用于其他 OpenAI 兼容服务。
- `KIE`：用于 KIE 原生异步任务接口。
- `Agnes`：用于 Agnes Video V2.0 官方异步视频接口。

### OpenAI

服务商明确提供 OpenAI 兼容接口时选择。项目会按功能使用以下接口：

| 能力 | 主要接口 |
| --- | --- |
| 模型列表 | `GET /v1/models` |
| 文本 | `POST /v1/chat/completions` |
| 生图 | `POST /v1/images/generations` |
| 图生图或图片编辑 | `POST /v1/images/edits` |
| Responses 生图 | `POST /v1/responses` |
| 视频 | `POST /v1/videos` 及对应任务查询接口 |

不同服务商可能只兼容其中一部分。能够返回 `/models` 不代表一定支持生图或视频接口。

### New API

New API 按 OpenAI 兼容接口接入，文本使用 `/chat/completions` 或 `/responses`，图片使用 `/images/generations` 和 `/images/edits`。后台图片模型测试只检查连接、鉴权和模型列表，不会创建收费图片。

### Sub2API

Sub2API 文本模型优先使用 `/responses`。由于不同部署版本对标准 Images API 和 Responses 图片事件的支持存在差异，生图应在工作台中使用流式 Responses 实际验证；后台不会用文本请求误判图片模型。

### 火山方舟

火山方舟用于 Seedance 官方视频任务。项目会把统一的视频创建与查询请求转换到 `/contents/generations/tasks`，后台测试只检查配置，不创建收费视频。

### KIE

只有上游兼容 KIE 任务接口时才选择。项目会将图片或视频生成请求转换为异步任务：

```text
POST /jobs/createTask
GET /jobs/recordInfo?taskId=...
```

KIE 模型的请求参数、参考图字段和结果会由后端转换。模型名必须使用项目支持且上游实际开放的 KIE 模型名，例如：

```text
gpt-image-2-text-to-image
gpt-image-2-image-to-image
```

不要因为模型名称看起来像 KIE 市场模型就选择 KIE；自建中转站如果提供的是 OpenAI 兼容接口，应选择 OpenAI。

### Agnes

Agnes 渠道用于 `agnes-video-v2.0`。建议配置：

```text
Base URL: https://apihub.agnes-ai.com/v1
模型名称: agnes-video-v2.0
```

项目使用 `POST /v1/videos` 创建任务，并优先使用创建结果中的 `video_id` 请求 `GET /agnesapi?video_id=...` 查询状态。任务完成后读取 `metadata.url` 作为视频地址。单张参考图发送 `image`，多张关键帧发送 `extra_body.image` 和 `extra_body.mode=keyframes`。

## 选择模型

点击“选择模型”后，可以通过两种方式添加：

### 拉取模型列表

- OpenAI 协议：后端请求渠道的 `GET /models`，使用返回的模型列表。
- KIE 协议：当前使用项目内置的 KIE 模型清单，不会向上游查询账号实际权限。
- Agnes 协议：可拉取模型列表，也可以手动添加 `agnes-video-v2.0`。

因此，列表里出现某个 KIE 模型并不代表当前 API Key 一定有权限调用。

### 手动添加

当上游没有 `/models` 接口、返回列表不完整，或服务商要求使用部署 ID 时，可以手动输入模型名并点击“增加模型”。

模型名区分字符，必须与服务商文档一致。文生图和图生图可能是两个不同模型，例如：

```text
gpt-image-2-text-to-image
gpt-image-2-image-to-image
```

如果只配置图生图模型，在没有参考图的文生图任务中可能会失败。

## 模型测试的含义

当前后台“模型测试”主要用于文本模型：它会向 `/chat/completions` 发送一条 `hi`。

因此：

- 文本模型测试成功，可以确认域名、鉴权和文本接口基本可用。
- 生图、图生图、视频和音频模型测试失败，不一定代表生成接口不可用。
- KIE 生图模型不能通过这项文本测试证明可用。
- KIE 的模型测试也不能验证 `/jobs/createTask`、任务轮询、额度或模型权限。

生成模型应在对应的生图工作台、视频创作台或画布节点中发起一次最小任务验证。测试时先使用单张、默认尺寸、无参考图和简短提示词，再逐步增加参数。

## 让渠道在前台生效

渠道保存后还需要确认：

1. 渠道已启用。
2. 渠道可用模型中包含目标模型。
3. 系统可用模型中存在该模型。
4. 默认生图、视频、文本或音频模型选择正确。
5. 普通用户使用后台渠道的开关已开启。
6. 前台刷新配置后，在相应能力的模型选择器中选择该模型。

同一个模型配置在多个渠道时，后端会按照权重随机选择。排查问题时建议临时只启用一个对应渠道，避免请求命中不同服务商。

## 常见问题

### 上游接口无响应或网络不可达

常见原因：

- 域名拼写错误
- 域名 DNS 无法解析
- 上游服务停机
- 服务器网络、代理或防火墙阻止访问
- TLS 证书异常
- Base URL 填入了错误路径

先在运行后端的机器上确认域名能够解析，并能访问服务商要求的 HTTPS 地址。

### 401 或 403

检查 API Key、请求头格式、套餐权限、模型权限和 IP 白名单。编辑渠道时 API Key 留空只会沿用已保存密钥，不会写入一个新的空 Key。

### 404

通常表示 Base URL 或协议不匹配。例如把 OpenAI 中转站配置成 KIE 后，项目会请求 `/jobs/createTask`，上游可能返回 404。

### 429

通常表示额度不足、频率限制或并发限制。检查服务商余额和限流规则。

### 拉取不到模型

- OpenAI 协议要求上游提供 `/models`。
- 上游没有模型列表接口时，使用“手动添加”。
- KIE 协议显示的是项目内置清单，不代表账号权限。

### 模型存在但前台看不到

检查渠道是否启用、系统可用模型、对应能力的默认模型，以及普通用户是否允许使用后台渠道。保存设置后刷新前台页面。

### 文生图成功，图生图失败

确认上游是否提供 `/images/edits`，或者 KIE 是否配置了对应的 image-to-image 模型。文生图模型和图生图模型不要混用。

## 推荐验证顺序

1. 核对服务商文档中的 Base URL、协议和模型名。
2. 确认后端机器可以解析并访问上游域名。
3. 新增并启用一个渠道。
4. 拉取模型或手动添加一个目标模型。
5. 保存渠道和系统设置。
6. 文本模型使用后台“测试”验证。
7. 生成模型到对应工作台发起最小任务验证。
8. 在 AI 调用日志中查看实际模型、渠道、请求路径、状态码和上游响应。
9. 单渠道验证成功后，再配置权重、多个模型和备用渠道。
